# 카운터 스캐너 식권 사용 (회원 QR)

손님이 앱에 **내 QR**을 띄우고, 식당 카운터의 QR 스캐너(Newland NLS-FR2780 등)가 읽어 식권 1장을 사용한다.
기존 방식(손님이 앱으로 매장 QR을 찍기)은 스캐너 고장·장부 결제 회원을 위해 그대로 남긴다.

## 흐름

1. 손님: 앱/웹 `QR` 탭 → **내 QR 보여주기** (기본). 서버가 60초짜리 서명 코드를 발급(`GET /v1/transactions/member-qr`), 화면에서 직접 QR로 그린다(외부 QR 이미지 서비스 사용 안 함). 50초마다 자동 갱신.
2. 식당: 카운터 PC/태블릿 크롬에서 `https://greeneatgo.vercel.app/counter` 를 열고 **식당관리자 계정**으로 로그인해 둔다.
3. 스캐너가 QR을 읽으면 키보드처럼 숫자 81자리 + Enter를 입력 → 카운터 화면이 `POST /v1/transactions/member-qr/redeem` 호출 → 큰 글씨로 결과(이름, 남은 식권) 표시 + 효과음, 4초 뒤 대기 화면으로 복귀.
4. 손님 화면은 잔여 식권이 줄어든 것을 감지해 "식권 1장 사용 완료"로 바뀐다.

## 코드 형식 (`services/api/app/services/meal_qr.py`)

- 숫자만 81자리: `81` + 회원 UUID(39) + 만료 epoch(10) + 일회용 nonce(10) + HMAC-SHA256 64비트(20).
- 숫자만 쓰는 이유: 스캐너는 키보드로 입력하므로 한글 IME·Caps Lock·키보드 배열에 영향받지 않아야 한다. QR은 숫자 모드로 버전 3(29×29)이라 화면에서도 잘 읽힌다.
- 서명 키: `MEAL_QR_SECRET` (없으면 `OTP_PEPPER`에서 용도 분리 파생). 새 시크릿 없이 배포 가능.
- 유효 60초(+시계 오차 5초). 캡처한 화면은 곧 만료된다.
- 중복 차감 방지: 차감 RPC의 idempotency key = `meal-qr:{user}:{nonce}`. 같은 QR을 두 번 찍으면 두 번째는 `duplicate=true`로 응답하고 추가 차감하지 않는다.

## 규칙

- 사용 처리 권한: 활성 `merchant_admin`만. 차감 식당은 **로그인한 식당관리자의 식당**(QR에 식당 정보 없음).
- 차감 로직은 기존 `/transactions/scan`과 같은 `consume_meal()` 공유: 일반 구매자 `consume_voucher`, 보조금 임직원 `consume_subsidized_voucher`.
- 장부 결제 임직원(보조금 없음)은 카운터 처리 거절(`LEDGER_NOT_SUPPORTED`) → 앱에서 매장 QR 방식 사용. 장부 결제는 손님 본인 토큰·GPS·식대 정책 검사가 필요하기 때문.
- 한 번 찍을 때 항상 1장.

## 스캐너 설정 (NLS-FR2780)

- 기본값(USB HID 키보드, 접미사 CR)이면 그대로 동작. 카운터 화면은 입력이 멈추면(120ms) Enter 없이도 처리한다.
- 접두사/AIM ID가 붙어도 서버·화면이 81자리 코드만 골라낸다.
- 화면 밝기가 낮으면 인식이 느릴 수 있다 — 손님 폰 밝기를 올리도록 안내.

## 카운터 기기

- 윈도우 PC(크롬)와 안드로이드 태블릿(USB-OTG로 스캐너 연결, 크롬) 모두 같은 `/counter` 웹 화면을 쓴다. 기기 교체 시 로그인만 다시 하면 된다.
- 화면은 입력칸에 계속 포커스를 유지한다. 다른 창을 띄우지 말 것.

## 키오스크(탭앤픽) 종이 영수증

- 식당 키오스크에서 발급한 종이 영수증 QR(영수증 발급 번호, 24자리 16진수)을 카운터 스캐너로 찍으면 1회 사용 처리한다.
- 확인: `GET {KIOSK_API_BASE_URL}/payment/{영수증번호}/verify` → `{"result": 0}`일 때만 유효. 그 밖의 모든 코드(1, 1000 등)는 "사용할 수 없는 영수증이에요"로 거절.
- 사용 기록은 그린잇 DB `kiosk_receipt_redemptions`(영수증 번호 unique)에 남긴다. **영수증 1장 = 1번 사용**(수량 정보가 API에 없음).
- 키오스크 API가 응답하지 않거나 인증서가 유효하지 않으면 사용 처리하지 않는다(통과 없음). 인증서 검사는 끄지 않는다.
- 설정: Vercel API 환경변수 `KIOSK_API_BASE_URL=https://api.tapandpick.com`. 비어 있으면 카운터에 "키오스크 영수증 준비 중".
- DB: `supabase/migrations/0069_kiosk_receipt_redemptions.sql` 적용 필요(테이블 추가만, 기존 데이터 변경 없음).
- 미해결(탭앤픽 팀 확인 필요, 2026-10-20 기준): 인증서 만료(2026-09-22)·중간 인증서 누락, 사용 후 환불 방지.
